# Borrowed globe runtime source contract

`createGlobeRuntime(canvas, options):GlobeRuntime` is the synchronous, borrowed-authority composition of immutable Earth `90e23b3` `createBabylonRuntime.ts`. The source retains the full map/camera/input/focus/terrain-preparation/navigation orchestration and binds already extracted engine helpers. It is prepared source, not a checked artifact or a bootstrap-compatible default. Type, lifecycle, packed-consumer and canonical adoption checks remain queued.

## Required owners and frame order

`GlobeRuntimeOptions` requires the host `renderer` selection and its existing `scene`, `scheduler`, `frameProfile`, `lifecycle`, `settings`, `clock`, `platform`, `mapPorts`, `sky`, explicit `terrainPreparation` policy, `budgets` and `log`. Scene and renderer must reference the same device. Root/core remains pure; runtime lives at `@foss-earth/engine/babylon`. Sky 0.1.0 is an optional public type peer, never a production implementation import.

The scheduler port deliberately excludes `stop`. Engine counts only its own continuous holds and releases only those on failure/disposal. Renderer lifecycle alone owns scene render, begin/end frame, resolution, context events, readiness settlement and presentation candidates. Engine never constructs a backend, scene, scheduler, settings registry or physics loop, binds a second global resize/visibility authority, or disposes renderer/lifecycle/Sky/profile/host scene/world root. Host lifecycle should omit its optional `applyClipping`: engine already follows geospatial clipping settings once through its camera helper.

The host existing scheduler binds `shouldKeepRendering()` and `minFrameIntervalMs()`. The latter retains the source live frame-rate-cap calculation. The host tick uses its same monotonic milliseconds:

```ts
let rendered = false;
try {
  lifecycle.renderFrame(() => globe.prepareFrame(nowMs));
  rendered = true;
} finally {
  globe.afterFrame(nowMs, rendered);
}
```

`prepareFrame(nowMs)` opens engine profiling/capture/focus caching, updates existing inertia/FOV handback, preparation camera, Google/raster streaming/coverage, invokes the optional external host frame callback, then ordinary framePreparation.prepare({nowMs,deltaSeconds,scene}), and finally calls supplied `sky.update()` without a new clock argument. It renders nothing. `isPreparingFrame()` lets renderer lifecycle avoid redundant requests while new content is about to be drawn. A second prepare without closing the boundary rejects. Failure closes that boundary. `afterFrame(nowMs)` samples displayed preparation geometry and closes capture/focus caching. Pass `false` after a failed render to close without sampling unpublished geometry. The supplied profile's `frame()` is called exactly once by prepare; the host must not open another profile boundary for this tick.

Renderer lifecycle begins its device frame before the prepare closure, so the profiling `engine frame` tag now describes that actual current host frame. The old bootstrap body tagged before its own later beginFrame call. This is a documented instrumentation ordering change, not a new frame authority. No device timing result is claimed.

Frame closure retires `inFrame`, `isPreparingFrame()` and the per-frame focus cache before calling the supplied terrain capture's `endFrame()`. That call is attempted once per opened engine boundary, including prepare failure, `afterFrame(nowMs,false)` and runtime destruction. A lone operation or capture failure is rethrown with its original identity, including a literal `undefined`; simultaneous operation and capture failures produce an `AggregateError` in operation-then-cleanup order. A capture begin failure still receives the source-compatible end attempt. Later `afterFrame` or repeated destruction does not retry that failed end. Separate owned disposal records let a throwing watcher/cancellation callback coexist with frame closure and release of the engine's holds. The watchdog handle is retired before its supplied stop is invoked. These repairs and causal cases are source-only and unrun.

The host `try/finally` above guarantees closure, but JavaScript can replace a failed `lifecycle.renderFrame()` exception if that `finally` also throws. Hosts that need both renderer-operation and globe-cleanup failures must catch each independently and aggregate them; Engine only aggregates failures occurring inside its own prepare/after-frame calls. No borrowed renderer/profile authority is disposed here.

## Actual map, input and Sky ports

`mapPorts.raster` consists of the existing `loadMapTexture`, terrain loader/lighting factory, public imagery device/capabilities/acquisition/cancellation ports, mesh CPU budget and logging. `mapPorts.google` consists of the actual third-party traversal/auth constructors, cancellation/signal combination, renderer readiness, supplied terrain lighting, response realm, request/timing/online/origin observations and log. `setCacheLimits` targets the host's shared HTTP tile cache. These are required even if startup uses the fallback, ensuring later map switches have actual dependencies. They create no alternate image broker, decoder, uploader or frame loop.

Raster/Google/fallback transitions retain outgoing coverage until replacement drawable coverage is adopted, preserve source attribution during switches, share focus positions within each rendered frame, retain focus choices/refinement, source keys, startup/streaming holds, automatic/detail feedback, download meter and lazy Map readings. Defaults remain atlas with the original legacy switch. Legacy per-tile `Texture/updateURL` remains outside hidden native decode/upload accounting. The separate `createBoundedMapTextureLoader` now feeds the optional public `asyncMapTextures` seam. That is prepared source requiring actual host metadata/readiness and canonical adoption; no complete bounded Atlas/legacy adoption is claimed. The feature imagery runtime retains its existing native context-restored observer; disposal/stale callbacks are now guarded and independently cleaned.

`platform` supplies explicit input and unused-input propagation realms/preferences, the same host clock, point-pick predicate, native cancellation/focus ports, hidden observation and AbortError factory. Engine binds its actual input, camera settings, `createGeospatialGlobeCamera`, `createGlobeInertia`, `createCameraClipping`, `createGlobeIntentMotion`, `createNavigationOwner` and `createNavigationCameraAdapter`; it copies no second motion implementation. Navigation preserves exact snapshots, lifted limits/presentation mask, camera velocity/turn/FOV continuation, still-held press/wheel handback, map/input suspension and conditional startup/streaming hold restoration. Device generation/loss/restoration subscriptions delegate to the supplied lifecycle. Actual restoration of retired device resources still requires host owner reconstruction/adoption.

`sky.attach(context)` receives source-compatible `isGround`, `getWorldMatrix`, `requestRender`, `onDownloadBytes` and `onLightingChange`, and returns `{runtime,detach}`. The host constructs or binds its actual Sky instance and owns its eventual `dispose`. The host binds actual `bindSkyReadingsAndNotes({settings,sky})` from `@foss-earth/sky/babylon`; returned `detach` removes that binding's subscriptions/readings/notes only. Engine never copies Sun/night-light formatting or notes. Its Sky facade subscriptions are engine-owned and cleaned on runtime destruction; Sky itself remains host-owned.

`observations.mapDebug` is an explicit opt-in, with optional `publishMapDebug(snapshot):stop` owned binding. Debug getters preserve the source counters/recent events. There is no query parsing, Window property assignment, capture construction or global app access. Terrain capture is an explicitly supplied bounded object.

## External camera and terrain preparation policy

`external:{worldRoot,running?,onFrame?}` borrows a generic host world root and active camera. It creates no application camera or simulation. Map transitions preserve an already active external camera. `onFrame(deltaSeconds)` runs once on the existing frame after map work; source renderer delta/clamp behavior is retained. The caller owns floating-origin/root movement. Generic `setExternalViewState`, `setExternalRunning` and `setExternalFrameCallback` replace construction coupling; source `setSimViewState`, `setSimRunning` and `setSimTick` remain exact method aliases. These aliases require explicit external ports; omitting them provides ordinary globe behavior. `getWorldRoot()` returns that borrowed root. No Flight or Campus implementation is imported.

`prepareTerrain` retains validation, coverage sample positions, overhead camera selection, progress/diagnostic redaction, timeout/abort/replacement, coherent displayed snapshots and two settled Google checks. It requires `TerrainPreparationPolicy.evaluate`, `fallback`, `requiredRasterQuality`, `sampleIntervalMs`, `stalledAfterMs` and `timeoutMs`. The pure options/progress/result/structural cancellation/validation records are public core exports.

Preparation settlement now retires shared tick/cancellation/view/radius and camera bookkeeping before invoking provided cleanup/progress callbacks. Timer stop, abort-listener removal, owned continuous-hold release and failure progress are each attempted despite another failure; the preparation promise settles once. A single failure keeps its identity, and multiple failures reject with `AggregateError` in operation-then-cleanup order. Cleanup failure after a ready result rejects that result. Initial progress/timer-registration failures also retire acquired preparation state; evaluation or progress failure during the displayed-surface sample rejects preparation and propagates to `afterFrame`, where capture cleanup is aggregated separately. Failed initial/tick progress is not invoked a second time to report its own failure. Normal cancellation, replacement, timeout and source-change failure retain their failed-progress report. Late timer callbacks are harmless after settlement; an eagerly firing supplied timeout waits for its returned stop handle before closing. No private timer or frame authority is introduced.

Supplied acquisition ports must clean any hidden resource when they throw before returning a cancellation handle. Hold callbacks must maintain their own acquisition/release contract if they throw; Engine cannot infer an unreturned timer or undo opaque native side effects. Full provider reentrancy, native camera callbacks, backend restoration and transactional restoration of host settings/device state remain unqualified. The bounded repair covers retained frame/preparation cleanup and promise settlement, not every callback in the map/terrain runtime.

The old evaluator's aircraft AGL/contact/clearance safety decisions and default spawn altitude are excluded from production engine. Flight must inject its own existing acceptance/placement policy; Earth may inject a globe-only policy. This is an explicit construction requirement, not a compatible implicit default. Retained mixed assertion registration requires the host adapter to supply its original policy. Engine streams/samples displayed geometry; it does not decide that an aircraft is safe to spawn.

`GLOBE_RUNTIME_PARAMETERS` exposes original source costs with count/ms units and bounds: fallback segments 96; ordinary/external Google startup waits 10000/120000 ms; preparation timeout/sample/stall 120000/200/15000 ms; recent debug capacity 100. Existing Renderer/Map homes are used, with no new tab. `createGlobeRuntimeBudgets(settings)` binds them to the one host registry. Hosts register these once and feed the returned monitor methods into their preparation policy. Actual terrain acceptance thresholds remain host-owned.

## Compatibility, prepared evidence and limits

The original runtime methods remain on `GlobeRuntime` (also the source compatibility type `BabylonRuntime`): terrain/surface/renderer/status access; geographic view/orbit-target settings; map metrics, detail/focus/source/terrain/automatic feedback; input mode/sensitivity/anchor/controller actions; frame request/continuous/pause/activity/download/streaming; world root and `setSim*` aliases; navigation acquisition/state/snapshot/place/glide/presentation/intents; device generation/events; profile, Sky facade and destroy. Status retains original `BabylonRuntimeStatus`, with `GlobeRuntimeStatus` alias. Backend selection/rendererForce, bootstrap, default registry/query activation and owned scene/root/profile/Sky teardown move explicitly to host composition. No `createBabylonRuntime` constructor alias disguises those required changes.

`fixtures/composition/LegacyGlobeRuntimeTests.ts` retains all immutable mixed assertions (25 direct registrations plus parameterized cases) behind `registerLegacyGlobeRuntimeTests(ports)`. Its host adapter must supply public packed runtime/renderer/Sky/settings, source leaf mocks, external root, one frame authority, teardown and the original terrain policy. No app implementation is copied. `tests/globeRuntime.test.ts` contains actual CPU NullEngine/lifecycle causal cases and owner-hold failure cases. Fourteen additional frame/capture and terrain-settlement cases use this same actual runtime and a supplied traversal leaf that never downloads; they do not replace the runtime with a fake implementation. They cover combined operation/cleanup failures, stale focus, retry/no-repeat closure, supplied watcher/Sky/capture failures, pending cancellation/destruction, progress/timer registration/removal failures, ready-result cleanup failure, nested evaluation/capture errors and eager supplied timeouts. `fixtures/globe-consumer.mjs` installs/imports only public package entries under the existing isolated ESM/CommonJS/declaration guards. All are unrun.

Map/Controls parameter and host sections require one supplied presentation refresh subscription. Map cache uses that same pulse with explicit monotonic clock/cadence, deduplicates in-flight inspection and suppresses late clear completion after destruction. It constructs no private timer; causal cases are prepared in `tests/mapCachePresentation.test.ts`.

Outstanding are reserved type/lint/tests/build/packed consumers, real retained mixed-host adoption, canonical runtime/settings/assets/lock/removal changes, async bounded legacy-map adoption, backend restoration and native/GPU qualification, clean lineage/final artifact/export pins, common CI conformance and actual remote admission. Existing POI entry snap and unknown physical height datum remain documented. Rollback retains canonical Earth and the original bootstrap until those actual public consumers pass; preserve atlas/legacy choice, IDs/defaults/migrations and all old evidence.

The current [async raster, ordinary frame and cleanup renewal](async-raster-and-cleanup.md) documents actual public ports, ownership/compatibility changes, causal source cases and remaining Atlas/native/cache gates. All remain UNRUN.

## Grab and zoom points

Where zoom acts is chosen per input family by four `choice` parameters, `input.<family>.zoomAnchor` for `mouse`, `trackpad`, `touch` and `nonPointer` (keys, controllers and on-screen buttons), with `input.showNavigationAnchors` for the markers (`NAVIGATION_ANCHOR_PARAMETERS` in `src/settings/catalogue/controls.ts`; the original contract is `docs/proposals/navigation-anchors.md` in foss-earth/research). The runtime reads them when a gesture starts, through `createNavigationAnchorService` (`src/babylon/navigationAnchorService.ts`), which picks the point on the displayed surface or the ellipsoid, keeps the session's pinned point and runs Pick point. Each gesture's anchors stay with its glide (`createGlobeInertia`); the camera zooms about them with `CameraController.zoomAbout`. A grab pan's ground point is marked from the press until its glide stops, through the same overlay, while `input.showNavigationAnchors` is on.

Rotation has no choice: every input turns and tilts about the compass target, whose orbit anchor the service resolves without a pick, and the camera turns with `orbitBy(pitch, heading)`, which keeps the target's latitude and longitude. The proposal also let rotation turn about the point under the pointer or the fingers (`input.<family>.orbitPivot`). That kept the point on screen but moved the compass to wherever the new line of sight met the ground; tilted toward the horizon it ran out tens of kilometres and jumped with the terrain (October 2026), so those parameters are gone. `CameraController.orbitAbout` still turns about a given point for a host that calls it.

- `GlobeRuntime.navigationAnchors` is the host's handle: `status()` (the pin, Pick point, why pinning is blocked, tracking, and what each family last used), `subscribe`, `togglePick`/`armPick`/`cancelPick`, `pinTarget` and `clearPin`. `createNavigationAnchorPinSection` (`@foss-earth/engine/panels`) builds the Controls → Orbit buttons from it; `createControlsPanel` adds it to the orbit section when given `navigationAnchors`.
- The note under each zoom choice says what it last did, such as "No pinned point; using compass target." or "Last used the point under the pointer.", and why a tracked point overrides it. A fallback never changes the saved choice.
- A navigation lease clears gesture anchors and cancels Pick point, and blocks pinning until it ends; the pin stays. Replacing the view (`setViewState`, `restoreNavigationSnapshot`, a new orbit target height) clears gesture anchors only. POI tracking makes the tracked point every gesture's anchor until it ends. Disposal releases the service, the markers and the notes.
- `platform.navigationAnchorMarkers(canvas)` draws the markers; the browser bindings supply `attachNavigationAnchorMarkers` (`src/browser/navigationAnchorMarkers.ts`). A host without it gets no markers and everything else.
- `NAVIGATION_ANCHOR_PRESETS` ("Pointer and touch anchors", "Compass-centered") are for a host's preset list; the FOSS Earth app registers them after its own.
- The pin is session state: never saved, exported or put in the URL. Navigation snapshots are unchanged (version 1).
